<threat_model>
## Trust Boundaries (Phase 1 — Plan 04 scope)

| Boundary | Description |
|----------|-------------|
| `fastlane/Matchfile` git_url → public visibility | If git_url ever points to a public GitHub repo, ALL certificates encrypted in that repo become visible to anyone who has decrypted them historically (or future leak) |
| local Bundler-managed Ruby env → fastlane gem and transitive deps | Some fastlane transitive deps build native extensions; a malicious gem in the dependency tree could execute code at install time |
| `Apps/CortexMac` Personal Team auto-signing → developer machine keychain | Local signing on dev machine; not in Phase 1 scope but adjacent — fastlane is the future automation surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04-01 | Information Disclosure | `fastlane/Matchfile` | mitigate | git_url is `file:///Users/donmega/Library/Cortex-fastlane-certs` — local-only, never traverses a network. Acceptance criterion explicitly forbids `https://github.com/` or `git@github.com:` prefixes. Phase 8 swap to private GitHub URL is gated by paid enrollment + MATCH_PASSWORD setup. ADR-0001 (Plan 05) records the constraint |
| T-01-04-02 | Information Disclosure | committed `fastlane/.env` or other secret-bearing files | mitigate | `.gitignore` (Plan 01) already excludes `fastlane/.env`, `Matchfile.local`, `*.p8`, `*.cer`, `*.p12`, `*.mobileprovision`. Plan 04 acceptance criteria explicitly check that no signing material was created |
| T-01-04-03 | Tampering | malicious gem in fastlane transitive dep tree | accept | fastlane is published by the Fastlane core team and is well-monitored; the Bundler `Gemfile.lock` pins exact transitive versions. Risk of supply-chain attack exists but is low-severity for a tooling gem at planning maturity. Phase 8 will revisit (gem signature verification, version bumps via Dependabot) |
| T-01-04-04 | Denial of Service | Bundler native-extension build failure | mitigate | `bundle install` failure is surfaced as soft failure in the SUMMARY; Plan 04 is non-blocking for the rest of Phase 1. The executor proceeds without Bundler if necessary; manual `gem install fastlane` is documented as fallback |
| T-01-04-05 | Repudiation | uncommented team_id leaking team identity | mitigate | Acceptance criterion: `fastlane/Appfile` MUST NOT contain an uncommented `team_id "..."` line. Even though the team_id alone is not a secret, leaving it commented out keeps Phase 1 honest about the deferred-enrollment state |
| T-01-04-06 | Spoofing | accidental Match URL pointing to attacker-controlled repo | mitigate | Acceptance criterion: Matchfile URL MUST start with `file:///`. Phase 8 swap will be a visible, reviewable diff |

ASVS L1 controls applied: V14.2 (build-tool integrity — Bundler `Gemfile.lock` pinning), V14.4 (sensitive data — secrets gitignored).
