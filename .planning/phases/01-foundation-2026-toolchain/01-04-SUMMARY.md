## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Installed Homebrew Ruby 4.0.3 to satisfy `bundle install`**
- **Found during:** Task 1, Step 5 (`bundle install`)
- **Issue:** macOS system Ruby 2.6.10 (vendored at `/usr/bin/ruby`) cannot build the json-2.7.6 native extension because Ruby 2.6 is end-of-life and its mkmf flags handling is incompatible with json gem 2.7.x's extconf. The error surfaced as `extconf failed, exit code 1` during `json-2.7.6` installation, which is a transitive dependency of `fastlane 2.230+`
- **Fix:** Ran `brew install ruby` to install Homebrew Ruby 4.0.3 (keg-only at `/usr/local/opt/ruby/bin/ruby`). Then re-ran `bundle install` using the Homebrew Ruby's bundler. All 95 gems including json 2.7.6 built cleanly. Plan explicitly anticipates this case in Step 5: "If `bundle install` fails due to native extension build errors ... confirm Xcode CLT is installed. If it still fails, document the failure in the SUMMARY and surface as a checkpoint"
- **Files modified:** None in repo; environmental change (`/usr/local/Cellar/ruby/4.0.3` installed via Homebrew). The repo's Gemfile and Gemfile.lock are unaffected -- the lockfile contains no Ruby version pin, so any modern Ruby (>= 3.0) can replay the resolution
- **Verification:** `/usr/local/opt/ruby/bin/ruby --version` reports `ruby 4.0.3`; `bundle install` exits 0 with `Bundle complete! 1 Gemfile dependency, 95 gems now installed`; `Gemfile.lock` contains `fastlane (2.233.0)` plus 94 transitive deps with sha256 checksums
- **Why Rule 3 (not Rule 4 architectural):** The fix did not change the project's architecture, schema, or library choices -- it only repaired the developer-machine Ruby environment so the existing Gemfile could resolve. No code-level decisions changed
- **Committed in:** `8fdce53` (the Gemfile.lock written under brew Ruby is the artifact recording the successful resolution)

### Environmental note: Ruby version not pinned in Gemfile

The Gemfile does not pin a specific Ruby version (no `ruby "X.Y.Z"` directive). This is intentional for Phase 1 -- pinning would force every consumer (including the future macos-15 GitHub Actions runner) to install the exact Ruby version. Gemfile.lock's resolved gem versions are reproducible across modern Ruby (>= 3.0); Phase 1 trusts that any reasonable contemporary Ruby works. If Phase 8 needs a stricter pin (e.g., for reproducible CI signing), add the directive then.
