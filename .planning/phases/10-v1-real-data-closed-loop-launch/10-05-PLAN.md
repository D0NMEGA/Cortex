<objective>
Build the RD-07 four-arm ablation on real spikes, and do it without disturbing the Phase-7 synthetic
regression fixture.

Purpose: two constraints collide and both must hold. RD-07 requires the ablation to run with the gain
re-fit on real residuals (Plan 10-03). D-09 requires `refit_bps.json` and
`check_refit_uplift.py`'s `refit_bps >= raw_bps` invariant to stay byte-identical and synthetic-scoped,
because a negative real-data finding must be publishable without turning the build red - a red build is
pressure to tune. But `KalmanFilter()` reads `KalmanConstants.K`, so the re-fit changes what
`CortexReFITBench --smoke` produces, and the CI byte-diff at `ci.yml:378-388` would fail.

The resolution holds the gain fixed for the regression fixture: the generator emits the Phase-7
default gain as `phase7BaselineK` alongside the fitted `K`, `KalmanFilter` gains an injected-gain init,
and `--smoke` uses the frozen baseline. The synthetic fixture then guards the FILTER CODE, which is
what it was always for, and is immune to a data re-fit. Separately, RESEARCH's own "Alternatives
considered" table recommends a separate executable for the real-data arms rather than a fourth `Arm`
case, so the real ablation lands in a new `CortexReplayBench` and `CortexReFITBench`'s two payload
structs are never touched.

Output: a frozen baseline gain, an injected-gain init, a byte-identical `--smoke`, and a four-arm
real-data bench that measures realized gain and smoothing per arm and reports BPS at both
normalisations.
</objective>
