## BLOCKER, verified and resolved by the planner on 2026-09-05 - read this before Task 2

**The failure.** `CortexMac` does not build on this machine at all. Reproduced twice by the
orchestrator and once independently by the planner, after `xcodegen generate`, with
Xcode 26.3 / macOS 26.2:

```
xcodebuild -project Cortex.xcodeproj -scheme CortexMac -configuration Debug   -destination 'platform=macOS' -allowProvisioningUpdates build

Cortex.xcodeproj: error: Cannot create a Mac App Development provisioning profile for
  "com.donovansantine.cortex.mac". Personal development teams, including "Donovan Santine",
  do not support the HID Virtual Device capability. (in target 'CortexMac')
Cortex.xcodeproj: error: No profiles for 'com.donovansantine.cortex.mac' were found.
** BUILD FAILED **
```

**Root cause.** `com.apple.developer.hid.virtual.device` is declared in all three signed targets -
`project.yml:99` (iOS), `:137` (Mac), `:194` (daemon), from which XcodeGen writes
`Apps/CortexMac/Cortex.entitlements:10`, `Apps/CortexiOS/...:10` and `Apps/CortexDaemon/...:10`. A free
Personal team cannot provision that capability. `-allowProvisioningUpdates` does not help; it only
surfaces the reason. The entitlement buys nothing at runtime here - `project.yml:134-136`'s own comment
says it is "DECLARED but INERT under free-team signing" because the live IOHIDUserDevice path is
`#if CORTEX_HID_LIVE`-gated - yet it blocks the build outright.

**Options considered, and the one chosen.**

| Option | Verdict |
|---|---|
| (a) Omit the HID entitlement for a capture-only BUILD, leaving every committed file untouched | **CHOSEN - proven to work end to end, see below** |
| (b) Paid Apple Developer Program enrollment | Rejected for this phase: it is gate 2 in this plan's own HUMAN-UAT list, already deferred, and D-15 declares v1 shippable with it deferred |
| (c) Abandon the GUI capture, headless evidence only | Rejected as the PRIMARY answer, adopted as the FALLBACK. D-16 wants a visible demo and the user wants a runnable portfolio artifact; but Task 3 makes RD-08's evidence independent of the recording so a capture failure cannot block the requirement |

**Why option (a) must be a build-time override and never a file edit.**
`Tools/scripts/hid-surface-policy.sh:168-170` REQUIRES the literal
`com.apple.developer.hid.virtual.device` in all three committed entitlement files. Editing
`Apps/*/Cortex.entitlements` or `project.yml` would fail that gate, contradict ADR-0002's HID story,
and remove the `entitlement` disclosure `readme-policy.sh` requires. XcodeGen also REGENERATES the
entitlements files from `project.yml`, so a hand edit would be silently reverted by the next
`xcodegen generate` anyway. The override therefore lives in a separate file passed on the command
line.

**The proven fix, executed by the planner on 2026-09-05 - reproduce these exact steps:**

```
xcodegen generate
xcodebuild -project Cortex.xcodeproj -scheme CortexMac -configuration Debug   -destination 'platform=macOS'   CODE_SIGN_ENTITLEMENTS=Tools/capture/CortexMac.capture.entitlements   -allowProvisioningUpdates build
** BUILD SUCCEEDED **
```

with `Tools/capture/CortexMac.capture.entitlements` being the committed
`Apps/CortexMac/Cortex.entitlements` MINUS exactly one key,
`com.apple.developer.hid.virtual.device`. Both `com.apple.security.application-groups` (load-bearing:
the shm IPC ring) and `keychain-access-groups` are KEPT, and the free team provisions both. Verified
afterwards:

```
codesign -d --entitlements - --xml <app> | plutil -p -
  com.apple.application-identifier  => 57YW6M29S7.com.donovansantine.cortex.mac
  com.apple.security.application-groups => [group.com.donovansantine.cortex.shared]
  keychain-access-groups            => [57YW6M29S7.com.donovansantine.cortex.shared]
  (no hid.virtual.device)
codesign -dvv <app> -> TeamIdentifier=57YW6M29S7
open <app>; pgrep -lf CortexMac              -> RUNNING, no AMFI SIGKILL
osascript ... name of every window            -> "Cortex"
screencapture -x -o out.png                   -> 3024x1964 PNG written
```

So the app builds, signs under the free team, launches, holds a window, and can be screen-captured
non-interactively. Nothing above required a paid account.
