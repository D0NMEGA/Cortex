<objective>
Take the BC1S NDT1 model (Plan 04-03) and run the two-step Core ML pipeline that produces the phase's deliverable: **(DEC-03)** trace the encoder→rates forward pass and `ct.convert(..., convert_to="mlprogram", ...)` to a `.mlpackage`, then **(DEC-05)** `coremltools.optimize.coreml.palettize_weights(mlmodel, OptimizationConfig(global_config=OpPalettizerConfig(mode="kmeans", nbits=4)))` on that package, characterizing the size reduction and the bounded reconstruction-loss delta.

Two load-bearing constraints from 04-RESEARCH.md:
1. **DEC-05 REQUIRES DEC-03 first** (Finding §0.2 + Pitfall #4): `palettize_weights` operates on an ALREADY-CONVERTED `mlprogram` MLModel, not a raw `.pt`. So Task ordering is convert → palettize.
2. **Phase boundary — conversion+palettization run on dev-Mac CPU; NO ANE work** (Finding §0.2): do NOT set `compute_units=.cpuAndNeuralEngine`, NO Instruments/residency, NO on-device latency. Those are DEC-06..12 / Phase 5. Conversion uses default/CPU compute units only.

This plan depends only on the model definition (Plan 04-03), not on the full training run (Plan 04-04) — it constructs its own short-trained/initialized checkpoint, because SC4 (size reduction + bounded delta) characterizes the conversion+palettization of the forward graph, which does not require full convergence. This lets Plan 04-04 and 04-05 run in parallel (Wave 3).
Purpose: DEC-03 + DEC-05 — the `.mlpackage` + 4-bit palettized package "ready for ANE conversion" (the Phase-5 hand-off).
Output: `convert.py`, `palettize.py`, three integration tests (convert / palettized-exists-smaller / loss-delta), and a size+Δloss characterization recorded in an evidence note.
</objective>
