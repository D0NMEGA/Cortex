<objective>
Build the CortexRender core: a platform-agnostic `WebgridFrameEncoder` that draws the 30x30
webgrid + velocity-driven cursor into a supplied `CAMetalDrawable` in a single Metal **compute**
pass, plus the `CAMetalLayer` configuration helper that both display-link adapters will reuse.

core whose time SC#2 will measure (≤0.4ms). It deliberately knows nothing about display links or
pacing — Plan 03 wires those over this core.

`CADisplayLink` path (RESEARCH Decision 2: "only acquisition+pacing differ"). Interface-first:
this plan defines the `WebgridFrameEncoder(drawable:, cursorPos:)` contract and the
`WebgridParams` uniforms struct that downstream plans consume.

Output: `Packages/CortexRender/Sources/CortexRender/{WebgridParams.swift, Webgrid.metal,
WebgridFrameEncoder.swift, MetalLayerConfig.swift}` + a unit test for the uniforms struct's
deterministic field layout, with the package manifest updated to compile the `.metal` shader and
add a test target.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| WebgridParams (CPU) → Metal compute kernel | A uniforms struct (cursor position, grid dims) crosses into the GPU kernel; the kernel writes the drawable texture based on it. |
| Compute kernel → drawable texture | The kernel writes pixels into the CAMetalDrawable's texture (framebufferOnly=false enables this write scope). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01-01 | Tampering | WebgridParams uniforms (cursor pos may be off-grid / NaN once the real producer lands) | mitigate | This plan's kernel maps pixel→cell defensively and the cursor disc is a distance test; a NaN cursor simply fails the `< radius` test (draws no disc) rather than corrupting memory. The authoritative position clamp lives at the integrator seam (Plan 02, D-04) — documented as the upstream invariant. |
| T-06-01-02 | Information Disclosure / Elevation | Compute kernel writing out-of-bounds of the drawable texture (`framebufferOnly = false` opens write scope per RESEARCH Decision 4) | mitigate | Kernel bounds-checks `gid` against `out.get_width()/get_height()` and returns early before any write; `dispatchThreads` is sized exactly to `drawable.texture.width/height`. No write can land outside the drawable extent. (Documents WHY disabling the CA framebufferOnly optimization is acceptable: the kernel is the sole writer and is extent-bounded.) |
| T-06-01-03 | Denial of Service | A pathological `gridColumns/gridRows` (e.g. 0) causing divide-by-zero in cell mapping | accept | Phase 6 producer is in-process and trusted; `grid30x30` hard-codes 30x30. Documented; a guard is cheap to add if the field ever becomes externally driven (Phase 7+). |

No network, no auth, no persistence, no external/untrusted input in this plan — the surface is GPU-write-scope and uniforms validity only. Web-app threats (SQLi/XSS/CSRF/authz) do not apply.
</threat_model>
